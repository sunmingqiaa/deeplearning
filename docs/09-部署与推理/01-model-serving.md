# 模型服务与批量预测

## 一句话理解

训练产物只有能被推理流程稳定加载和调用，才算真正进入工程闭环。

## 核心知识点

- checkpoint：保存模型参数。
- 前处理：把请求或原始数据转换成模型输入。
- 后处理：把模型输出转换成业务结果。
- 在线推理：单条或小批量请求，重视延迟。
- 离线预测：大批量数据，重视吞吐和稳定性。
- 版本管理：模型、特征和代码需要能对应起来。

## 对应实验

批量预测：

```bash
python3 labs/week11-model-serving/scripts/batch_predict.py
```

HTTP 推理服务：

```bash
python3 labs/week11-model-serving/scripts/serve_linear_model.py --port 8000
```

然后访问：

```text
http://127.0.0.1:8000/predict?x=2.5
```

## 验收问题

- 训练时和推理时的前处理为什么必须一致？
- 在线推理和离线预测关注点有什么不同？
- 模型版本如何和特征版本关联？
- 为什么服务返回结果需要做输入校验？
